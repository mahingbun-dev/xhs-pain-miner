## [Unreleased]

### Added — M2 竞品调研可信化
- **竞品调研改用「解法词」而非「痛点名」**：痛点名描述的是"问题"，而竞品是
  "解法"，两者词汇没有交集。实测 `防晒搓泥` 在 App Store 上 **0 命中**、在 GitHub
  上只命中一条**无关的**书籍收藏仓库 —— 而 M1 把这两种结果**都**误读了：0 条读成
  「查证过确实没有竞品」，无关的读成「已有活跃竞品」。用户会因此去做一个实际
  已有百度网盘（92 万评分）这类强势竞品的红海方向。现在由 LLM 把痛点翻译成
  「用户会去找什么工具」（如 `美妆 成分查询`），并按渠道给出不同语言的词
- **竞品结论升级为四值状态**：`查到竞品` / `查证过，确实没有` / `检索不到，
  无法判断` / `调研失败`。此前"没查到"只有"有/没有"两种取值，于是**检索不到**
  被当成了**确实没有**。只有"平台返回过内容但都不相关"才允许给出满分空白度
- **App Store 渠道**（iTunes Search API，官方、免费、无需鉴权），与 GitHub 并列
- **相关性判定**：用 LLM 判断每条结果是否真的在解决该痛点，滤掉误报
  （实测 `防晒搓泥` 会命中一个 2.3 万星的**个人书籍收藏**仓库，
  `notes export` 命中的全是 Evernote / Notion 等**别家产品**的导出器）
- **检索轨迹**：报告里能看到实际搜了什么词、发给了哪个平台、平台回了几条、
  留了几条。这是"结论可逐条复核"的落地 —— 没有它，「查证过，没有竞品」
  无法被质疑
- **`tools/eval_research.py`**：用三组对照（痛点名 / 解法词 / 无关噪声词）
  跑真实检索，把召回与误报变成可复现的数字

### Changed — 竞品调研的口径
- 多渠道合并**保守优先**：任一渠道没查成，整体就不能断言"没有竞品"——
  那个渠道里可能正躺着一堆竞品。同渠道内某条检索词没查成时，也不能据此断言
  "查证过确实没有"；但若**已经**查到相关竞品，结论仍是「查到竞品」（已经拿到
  真实竞品就不该反过来说"没查成"），只在报告里标注清单可能不完整
- **关于"分数怎么算"的主张，只能由知道最终结论的那一层发出**：渠道层与轨迹层
  都不知道合并结果，它们说的话被原样拼进最终结论后就可能是假的（见下方 Fixed）
- 竞品条目新增 `description`（平台上的公开描述），它是相关性判定的主要依据
- 检索轨迹**不进上传载荷**：检索词是 LLM 生成的自由文本，而生成它的提示词里
  带了用户原话（模型可能回抄），因此它属于"必须先过回抄检测"的那一类

### Fixed — M2 自审（独立验证推翻了两条论证后修的）
- **「其「竞品空白度」按中性值计」由渠道层说了不该它说的话**：渠道警告会被
  `ResearchOutcome.merged` 原样拼进最终结论，而另一个渠道查到竞品时空白度并**不是**
  中性 —— 实测报告里同时出现"按中性值计"和一张按竞品算出的空白度（0.5155），
  与 M2 要消灭的自相矛盾是同一类。分数主张改由**读合并后卡片**的那几层说
  （`_unresolved_warning` 与渲染层的卡片结论）—— 只有它们知道最终结论
- 同一根因的另外两处：检索轨迹曾自带"该簇的竞品空白度必须按中性值处理"
  （在"已查到竞品 + 同渠道另一条检索词被限流"这条**可达**路径上是假话）、
  `research/appstore.py` 的 `Raises:` 契约也这么写
- **"检索不到"笼统盖住了另外两种成因**：`unsearchable` 的文案把该渠道全部检索词都说成
  "在该渠道没有返回任何结果"，而其中可能既有被限流的、也有**平台返回过内容但都不相关**的
  —— 后者的产物里会同时出现"没有返回任何结果"和轨迹行的"命中 5 条 · 保留 0 条"，两句打架。
  现按**三种成因**分开说：返回 0 条 / 返回过但不相关 / 这次没查成（各带自己的下一步动作）
- **卡片不提示"竞品清单可能不完整"**：渲染层判据写的是 `research_failed`，而有
  findings ⇒ 状态必是 `ok` ⇒ 它恒为 `False`，于是这条真实场景两张产物上一个字都不提
  （而 `render/html.py` 的注释本就写着"都必须说"——注释描述了意图，判据没实现它）。
  新增派生属性 `OpportunityCard.research_incomplete`，HTML 与 Markdown 共用同一份判据
- 文档：`docs/architecture.md` 里 `ok` 的空白度上界写成「≤ 0.60」，而竞品全部停更时
  是 0.75；`### 4.6` 与 `### 4.5` 的编号顺序颠倒

### Fixed — M1 遗留
- **降级文案失实**：警告无条件说"已降级为占位名"，而默认路径上根本不会写占位名
  ——报告在系统性地指向一个并不存在的「待命名方向」
- **噪声桶稀释提及量**：归一化基准曾取"全部簇"的最大 size，而噪声桶常是全语料
  最大簇、且已被挡在卡片之外，等于用分类质量差去惩罚真实痛点
- 报告里 4 处声称"附带完整检索轨迹"，而产物里根本没有轨迹

### Added — M1 核心链路
- **`mine` 子命令**：采集 → 清洗 →（可选 VLM）→ 向量化 → 痛点归集 → 标注 →
  竞品调研 → 机会分 → HTML/Markdown 报告，端到端跑通
- **清洗层**：去重、广告引流过滤、低价值互动过滤、零宽字符与全半角规范化
- **向量化**：本地 `bge-small-zh`（零成本，默认）或任意 OpenAI 兼容的
  `/v1/embeddings`
- **痛点归集**：LLM 归纳痛点清单 + embedding 分类 —— 见下方 Changed
- **痛点标注**：情感极性、增长趋势、实现难度与人话描述
- **VLM 图片分析**（`--deep`）：内容去重、512px 压缩、SQLite 缓存、并发限流、
  失败降级、开跑前成本预估
- **竞品调研**：GitHub Search API，含限流识别与"失败 ≠ 没有竞品"的严格区分
- **机会分**：五因子可解释加权，权重可调、逐因子可溯源
- **报告**：自包含单文件 HTML（含证据链与因子溯源）/ 不含原文的 Markdown
- **`--weights "gap=0.4,trend=0.3"`**：命令行调整机会分权重
- **`tools/eval_clustering.py`**：把验收门③的频次误差变成可复现的数字
- **`tools/smoke_m1.py`**：离线端到端联调

### Changed — 痛点归集方案从「聚类」改为「LLM 归纳 + 分类」
M1 开发中发现 HDBSCAN 在中文短文本上不可用：1142 条文本聚出 **171 个簇**，
而语料里只有 10 个真实痛点（purity 0.996 但 coverage 0.095）—— 一个 130 条的
真实痛点被切成 16 片，每片 `size` 只有 8，**用户一核对就会发现对不上**。

根因是中文短文本的语义信噪比只有 0.06-0.09（手写对照语料 0.062、内置合成语料 0.087），
四条独立证据（换 bge-large 只提到 0.08、
调参、簇合并、手写自然语料对照）都指向同一结论。改用「LLM 归纳清单 + embedding
分类」后准确率达 **0.803**，LLM 调用从「每个簇一次」（实测 171 次，因为聚类碎成了
171 片）降到「1 次归纳 + 每个痛点 1 次标注」（10 个痛点 = 11 次）。
`PAIN_DISCOVERY=cluster` 可切回聚类路径用于对比。

### Fixed
- **「提及量」因子失去绝对锚点** —— 它原本兼作置信度（只说了一次的痛点可能是个人
  怪癖），但归一化基准取「参与机会评估的簇的最大 size」之后，任何语料里最大的痛点
  恒等于 1.0（`log1p(max)/log1p(max) ≡ 1`）：只被 12 次提及的痛点在薄语料里会和
  543 次提及的同分，"兼作置信度"名存实亡。现补一个有界的绝对置信度项（50 次提及
  饱和）与相对项相乘。**机会分口径随之变化**：`size < 50` 的痛点提及量与总分会被
  重算（543 次语料里 17 次提及的痛点由 0.459 降到 0.337），薄语料里的头名不再满分，
  报告新增一条语料规模提示；`size ≥ 50` 的痛点分数不变
- `LabelCluster` 的 `difficulty` / `feasibility` 未写回 `PainCluster`，
  会让「实现难度」因子永久返回中性值
- `Evidence` 缺 `created_at`，会让「增长趋势」因子永久返回中性值
- 归纳出痛点但缺少打标样本时，全部文本会被塞给唯一质心，产出一个
  看着正常却毫无意义的提及次数（改为用痛点名向量补质心并告警）
- LLM 完全不可用时流水线整体失败（改为降级到聚类路径并如实说明）
- `doctor` 对分析依赖只给 `warn`，而 M1 起缺了它 `mine` 完全跑不起来

## [0.1.0] - 2026-09-15 — M0 骨架

### Added
- **配置层**：LLM / VLM / Embedding / Collector / 限额 / 隐私六组配置，全部可通过环境变量或 `.env` 注入
- **LLM 协议适配层**：`chat`（OpenAI Chat Completions，兼容 DeepSeek / Qwen / Kimi / GLM）、
  `responses`（OpenAI Responses API）、`messages`（Anthropic Messages API）
- **采集后端协议**：`CollectorBackend` + 插件加载器（支持模块路径与 `.py` 文件路径）+ 内置脱敏样例数据
- **`doctor` 子命令**：诊断 Python 版本、依赖、模型配置、采集后端与路径权限，不发起网络请求
- **`collect` 子命令**：只做采集并打印统计，支持 `--save` 导出原始语料
- **领域模型**：`RawNote` / `RawComment` / `PainCluster` / `Evidence` / `CompetitorFinding` /
  `OpportunityCard` / `RunCost` / `MiningResult`
- **合规设计**：`to_public_dict()` 脱敏导出契约 + `hash_id()` 个人信息哈希 +
  `find_verbatim_overlap()` 原文回抄检测 + 默认关闭的众包开关
- 文档：竞品与合规分析、架构设计、采集后端插件指南

### Changed
- **项目定位**：从「给品牌方做小红书舆情看板」转向「给独立开发者发现可做的产品机会」
- **核心交付物**：从「痛点排行榜」改为「机会卡片 + 可解释机会分」
- **CLI 子命令**（破坏性变更）：`analyze` 更名为 `mine`（语义更贴近"挖掘机会"）、
  `serve` 移除；新增 `collect`（只采集，用于验证采集层与配置）与 `doctor`（环境诊断）
- **许可证**：MIT → **AGPL-3.0-or-later**（核心引擎）+ MIT（Skill / 文档 / 示例）双许可
- **包结构**：统一到 `src/xhs_pain_miner/`，删除 6 个空占位包；
  按职责划定模块边界 —— `llm/` 与 `collectors/` 已在 M0 落地，
  `pipeline/`、`research/`、`scoring/`、`render/`、`storage/` 自 M1 起逐步落地
- **依赖分层**：核心依赖保持轻量，计算密集型依赖（numpy / scikit-learn / sentence-transformers）移入 `[analysis]` extra

### Fixed
- **打包配置失效**：`build-backend` 是无效值（`setuptools.backends._legacy:_Backend`），
  且缺少 `package-dir` 配置 —— 导致 `pip install -e ".[all]"` 装不出可导入的包
- **`.gitignore` 误伤**：`data/` 会连带忽略 `src/xhs_pain_miner/data/` 下的内置样例语料，导致其无法提交
- **配置静默失效**：`load_settings()` 拼错字段名会被 pydantic 的 `extra="ignore"` 静默吞掉
  （典型症状：用户传了 API Key 却没生效），现改为显式报错
- **终端输出**：`doctor` 的 `pip install -e ".[analysis]"` 被 rich 当成样式标签吃掉，
  且完整 API Key 会出现在输出里（现为脱敏显示）
- **危险的文档建议**：FAQ 中"建议使用代理和多个 Cookie 轮换"已删除 ——
  这正是判例认定"规避技术管理措施"的行为模式

### Removed
- `src/` 下的占位包：`crawler/`、`analysis/`、`vlm/`、`miner/`、`visualize/`、`api/`
- `serve` 子命令与 `web/`（Next.js）从 M1–M4 范围中移除，避免成为时间黑洞
