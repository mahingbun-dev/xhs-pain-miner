> 调研日期：2026-09-15。标注 **[查证]** 的结论有可引用来源；**[推测]** 为基于证据的推断。
> 本文件用于支撑产品方向决策，**不构成法律意见**。涉及具体法律行动前请咨询执业律师。

## 一、结论先行

1. **"搬运数据"这条路已被三面封死**：上游是官方免费洞察平台，下游是法院判例，技术上是反爬风控。
2. **判例的真实红线是"绕过技术保护措施 + 规模化售卖数据"，不是"采集公开数据"**。这给"只交付结论、不交付数据"留了一条窄但真实的路。
3. **空白区在"洞察层"**：现有工具做的是"关键词命中 + 正负面判定"（检索），没有一家做"痛点归纳 + 竞品空缺 + 机会评分"（发现）。
4. **窗口期不长**：GitHub 上已出现同构的开源项目。

## 三、合规与判例

### 3.1 民事判例

| 案件 | 行为 | 结果 |
|---|---|---|
| **小红书诉蝉妈妈/蝉小红**（杭州中院 2025-04 终审） | 频繁换 ID、加速换 IP **绕过技术保护措施**抓取，会员收费对外提供 | 赔 **490 万**，停止服务、删除数据、登报消除影响；官网已关停 |
| **小红书诉数某/秀某**（上海知产法院终审） | "小红书接口集合"，调用 294 万次，违反 Robots 与频率限制 | 赔 **110 万**；确立"**即使单个数据可公开获取，大规模数据集合仍受保护**" |
| **小红书诉固某科技**（福建高院，入选最高法 2023 年 50 件典型知产案例） | 仅批量下载本就公开、带水印的内容 vs 修改 MD5 | **仅批量下载不构成不正当竞争**；修改 MD5 构成。判 15 万 |
| **大众点评诉百度**（上海浦东 2016） | 百度地图大量全文使用点评信息 | 判 300 万 + 23 万；确立"**实质替代**"标准 |
| **淘宝诉美景「生意参谋」**（2017） | 转卖数据产品 | 认可竞争性财产权益，判 200 万 |
| **微博诉脉脉**（北京知产法院 2016 终审） | 抓取并使用用户头像、名称、职业 | 判 200 万 + 20.9 万；确立"**三重授权原则**" |
| **最高法第 47 批指导性案例 262 号**（2025-08-27） | 数据抓取标杆 | 要件：**未经许可获取 + 实质性替代 + 三元利益损害** |

来源：[知产财经](https://www.ciplawyer.cn/articles/157825.html) · [南都](https://m.mp.oeeee.com/a/BAAFRD0000202504271078619.html) · [澎湃](https://m.thepaper.cn/newsDetail_forward_33043279) · [海淀法院](https://bjhdfy.bjcourt.gov.cn/article/detail/2016/04/id/4015255.shtml)

### 3.2 刑事判例（真实入刑）

- **郴州北湖案**：爬取抖音直播用户抖音号/手机号/昵称，判 **3 年 6 个月至 1 年 3 个月**。
- **常州天宁案**：绕过加密获取昵称/userID/noteID 并破解私信接口，违法所得 600 余万，单位罚金 20 万、6 人判 3 年至 1 年 9 个月。
- **入刑门槛**：侵犯公民个人信息罪普通信息 5000 条 / 敏感 500 条 / 核心 50 条。

### 3.3 法律约束

- **《反不正当竞争法》2025 修订**（2025-10-15 施行）：原第 12 条"互联网专条"扩为**第 13 条**，
  **新增第 3 款** —— 不得以欺诈、胁迫、**逃避或破坏技术管理措施**等不正当方式**获取、使用**其他经营者
  合法持有的数据。此前大规模公开数据抓取只能靠第 2 条兜底，现在有了专门条款，**原告举证难度显著下降**。
- **《个人信息保护法》**：昵称（含系统自动生成）、头像、UID **均被认定为个人信息**。可处理"自行公开"的
  个人信息，但须在**合理范围内**。
- **小红书 `robots.txt` 为 `Disallow: /`** —— 可被直接引用的"平台明确拒绝"证据。

### 3.4 降风险做法评估

| 做法 | 降低的风险 | **不降低**的风险 |
|---|---|---|
| 本地运行、数据不上传 | 打掉 262 号"向公众提供/实质性替代"要件；大幅降低个保法责任 | 用户自身封号；"提供工具"的帮助侵权 |
| 只用用户自己账号的 Cookie | 补上"三重授权"中的用户授权 | **补不上"平台授权"** |
| 只做聚合结论、不落原文与 UID | 几乎不可能触及刑法 253 条之一 | 新反法 13 条第 3 款同时规制"**获取**"与"**使用**" |
| 接入官方 API / 持牌数据商 | 合规性最高 | 成本高、字段受限、需企业资质 |

**必死三路**：
1. 自建爬虫 + 公开 SaaS 收费卖数据（复刻蝉小红案的行为模式）
2. 逆向签名 + 换 IP/换 ID 规模化采集（自证"逃避技术措施"）
3. 碰直播、私信、非公开内容（直接落入刑法 285 条）

### 三条对定价的启发

1. **credit 是最佳抽象层**（Productboard / UserCall / Listen Labs 一致采用）—— 不暴露 token 成本，
   却能随推理成本浮动。
2. **不要按"报告数"计费**：报告是一次性产物，用户截屏后即流失，无复购。应按**可重跑的持续采集额度 + 时间序列**计费。
3. **免费额度必须能跑通一次完整价值**（Dovetail 1 channel、Marvin 5 文件/月、Productboard 50 credits/月）。

### 护城河排序（可持续性由高到低）

1. **独家数据通道** —— 真壁垒
2. **工作流嵌入位置** —— Cycle 被收购的本质是"Jira Product Discovery 里没有 AI 功能"
3. **纵向可比基线**（"这个痛点同比涨 300%"）—— 单次分析做不到，需要历史数据
4. **编码体系 / taxonomy**
5. 报告呈现 —— **≈ 0 壁垒**

**模型不是护城河，数据获取是；但报告呈现也不是 —— 能点回原文、能重跑出趋势的报告才是。**

## 六、对本项目的直接含义

1. **不要做"又一个千瓜"** —— 数据层已被官方免费灵犀 + 判例 + 风控三面封死。蝉小红是前车之鉴。
2. **只交付洞察，不交付数据** —— 卖"痛点地图 + 机会评分"，不卖"笔记评论数据"。
3. **采集层隔离** —— 仓库不携带任何第三方采集实现，通过插件协议让用户在本机自备。
   这同时解决许可合规与权属干净两个问题（详见 [collector-plugin.md](collector-plugin.md)）。
4. **差异化押在三点**：可解释机会分（权重可调、因子可溯源）+ 竞品调研（GitHub/应用商店/站内）
   + 证据链（每条结论可点回原文）。
5. **定价瞄准价格带空白**：现有工具 ¥168–3000/月，"个人开发者"价位无人服务。
